# 3 分钟演示脚本

目标：让面试官在 3 分钟内看到“问题 → 现场运行 → 结论 → 证据 → 边界”。
不要念 PPT，不要讲“企业级平台”。

## 0:00–0:20 开场

画面：终端，光标停在项目根目录。

旁白：

> Coding Agent 写代码越来越快，但团队真正卡住的是最后一步：这次改动到底能不能交付？
> 密钥有没有进去，危险命令有没有合进去，运行有没有超预算，出了事能不能查。
> 我做了一个本地闸门，只输出三个结论：block、fix、ship。

## 0:20–0:50 现场跑

画面：输入命令。

```bash
python scripts/demo.py
```

旁白：

> 这条命令会真实创建一个 AgentSpec，跑一次 run，再把这条 run 和安全评审关联。
> 不是静态截图，也不是 mock。

画面：出现 `run status: completed`、`verdict: block`、`CS-PY-003 deploy.py:6`。

旁白：

> 结论是 block。原因是 `shell=True` 拼接外部输入，属于命令注入。
> 同一份报告里还有行为预算：Token、时长、工具调用全部 pass。

## 0:50–1:35 UI 与豁免

画面：切到桌面应用「安全评审」页。

旁白：

> 页面首屏先给结论，再给依据。每个问题有文件行号、脱敏证据、中文修复建议，
> 以及它违反了哪条公司规范。这里 SEC-03 明确禁止把外部输入拼进 shell。

画面：点「申请限时豁免」，填 owner、理由、到期时间。

旁白：

> 风险不是不能接受，但必须有责任人、有理由、有到期时间。过期或撤销后，
> 风险会重新计入阻断。这样企业才敢用，而不是加一行 `# nosec` 就永久消失。

## 1:35–2:10 独立基准

画面：打开 `docs/verification/security-benchmark.md`。

旁白：

> 我没有拿自己写的样本证明自己。基准固定了两个公开漏洞项目的 commit，
> 标签是人工读源码写的，扫描器不参与出题。
> 整仓库不过滤精确率 16.7%；修掉 RegExp.exec、字符串 eval、占位符密钥三类误报
> 后到 22.7%；默认忽略 vendor、教程和压缩产物后到 62.5%；再加有期白名单到
> 100.0%。召回率始终是 71.4%。
> 三个数字我都公开，因为降噪过程本身才是工程能力。
> 明确不覆盖 XSS、XXE、XPath 和 NoSQL，所以它不叫完整 SAST。

## 2:10–2:40 CI 与 SARIF

画面：打开 `.github/workflows/security.yml` 或 SARIF 文件。

旁白：

> 同一条命令可以进 CI。默认阻断时退出码是 1，同时输出 SARIF 上传到
> GitHub Code Scanning。也就是说，它不是演示页，是能卡住合并的闸门。

## 2:40–3:00 收尾

画面：回到结论页。

旁白：

> 这个项目现在还不是行业级工具：没有 3 个真实用户，规则也只有 31 条。
> 但它把“能不能交付”这件事做成了可复现的结论，而不是一堆看不完的日志。
> 下一步我会用真实用户卡点降误报，再补跨文件数据流。

## 录制检查清单

- 终端字号 ≥ 18，深色主题，提前清屏。
- 不要录到 API Key、内网地址、真实公司路径。
- 先跑一遍确保 `.demo-workspace` / `work/demo` 可重建。
- 视频描述里放仓库链接、基准报告链接、复现命令。
- 3 分钟内不解释 LangGraph、MCP、Worker，这些留给面试追问。
