# 第二个旗舰项目：MCP Trust Bench

日期：2026-11-14
状态：**已选型，待开工**
前两版（TestWitness、Agent Blackbox、MCP Guard）的否决理由见文末。

## 先说结论

**不做第七个扫描器，做它们的裁判。**

MCP 安全扫描器已经有 Snyk、NVIDIA、Cisco、腾讯、IBM、微软在做。但**没有一个公开、
可复现、带人工标签的基准**告诉企业：这些扫描器到底能抓到多少、误报多少、慢不慢。

MCP Trust Bench 就是那个基准，外加一个把多家扫描器结果合并成一份结论的运行器。

## 为什么这个位置打得过

| 维度 | 再做一个扫描器 | 做基准 |
| --- | --- | --- |
| 竞品 | 6 个以上成熟项目 | 没有公开基准 |
| 胜负判定 | 谁规则多、谁融资多 | 谁的标签可信、谁可复现 |
| 个人能做吗 | 很难赢 | 能，2–3 周可出第一版 |
| 面试杀伤力 | “你和 Snyk 比呢” | “你怎么保证标签不偏？”——这题你能答 |
| 与 Crossbar 的关系 | 两个安全产品并列 | 同一个方法论：独立基准 + 公开数字 |

它和 Crossbar 是同一条主线：

> **我不只会写闸门，我还会证明闸门有用。**

Crossbar 已经用两个公开漏洞项目做过独立基准；这个项目把同一套方法论搬到 Agent 工具层。

## 一句话

**给 MCP 安全扫描器做一份公开、可复现、带标签的考试，并把多家的结果合成一个结论。**

## 用户是谁

- 要在几款 MCP 扫描器/网关之间选型的安全团队。
- 需要向管理层证明“我们扫过了”的平台团队。
- 扫描器作者自己：需要一个第三方基准证明规则有效。

## 交付物

1. **语料库**：40 个可运行的 stdio MCP server。
   - 20 个恶意，覆盖 10 类攻击：工具描述投毒、不可见 Unicode、越权文件读、
     命令注入、密钥回传、假工具名、schema 与描述不符、超长描述淹没上下文、
     远程明文传输、依赖混淆。
   - 20 个良性，但行为真实（文件、HTTP、数据库、Git），用来测误报。
   - 每个样本一个 `case.yaml`：攻击类别、期望检出点、证据、作者、复核人。
2. **适配器**：至少 3 家外部扫描器 + 1 个自写基线。统一输入输出。
3. **指标**：每家的精确率、召回率、按攻击类别的召回、扫描耗时 P50/P95。
4. **报告**：`mcpbench report` 输出 HTML + JSON + 一张排行榜。
5. **CI**：每周重跑，扫描器升级导致指标变化时开 issue。

## 架构

```
cases/            40 个样本 + case.yaml 标签
adapters/         snyk / cisco / nvidia / baseline，统一接口
runner/           启动样本、调用扫描器、收集 findings
metrics/          标签 vs findings → 精确率/召回率/耗时
report/           HTML + JSON + leaderboard
cli               mcpbench run / report / verify-labels
```

适配器接口只有一个方法：

```python
class Scanner(Protocol):
    name: str
    def scan(self, server: Path) -> list[Finding]: ...
```

Finding 只保留：`case_id`、`rule`、`severity`、`path`、`line`、`message`。
这样任何扫描器都能接，不需要它支持我们的格式。

## 3 分钟演示

1. `mcpbench run --scanner snyk`：扫 40 个样本，出混淆矩阵。（40 秒）
2. `mcpbench report`：打开 HTML，看每家在 10 类攻击上的召回柱状图。（60 秒）
3. 指着一个“所有扫描器都漏掉”的样本，讲为什么：描述投毒需要语义理解，
   正则规则抓不到。（40 秒）
4. `mcpbench verify-labels`：演示标签是人工复核的，不是模型生成的。（40 秒）

## MVP：3 周

| 周 | 交付 | 验收 |
| --- | --- | --- |
| 1 | 20 个样本（10 恶意 / 10 良性）+ 标签格式 + runner | `mcpbench run --scanner baseline` 能跑完并出混淆矩阵 |
| 2 | 补到 40 个 + 接 2 家外部扫描器 | 两家都能跑通；结果可复现（同输入同输出） |
| 3 | 指标、HTML 报告、CI、文档 | 公开一份完整报告；README 写清标签来源与局限 |

## 必须公开的数字

- 每家扫描器的精确率 / 召回率 / F1。
- 按攻击类别的召回（哪类谁都抓不到）。
- 扫描耗时 P50 / P95。
- 误报分类：哪些是规则问题，哪些是样本写得不像真实业务。

## 风险与红线

- **标签偏见**：样本是我写的，我知道答案。缓解：标签由第二个人复核；
  恶意样本尽量改写自公开披露的真实案例，并注明来源。
- **样本不像真的**：良性样本必须能真的读写文件/发 HTTP，不能是空壳。
- **被说“你这不是产品”**：它就是基准 + 运行器，不是 SaaS。定位写清楚，
  反而更难被挑。
- **红线**：不编造扫描器分数；跑不出来的数字不写；不贬低具体厂商，
  只报实测。
